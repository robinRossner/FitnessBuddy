# Refactoring plan: faster tests, cleaner layers, room for new features

Written 2026-11-02 from a survey of the repo (backend, iOS, tooling).

## Status (2026-11-02, branch `refactor-2026-11`)

Implemented: Phase 0, Phase 1 (all), Phase 2 (all; `lifting.py` left whole, settings threading in
`analytics/` skipped), Phase 3 (all), Phase 4 (all except pre-commit being installed locally).

| Measure | Before | After |
| --- | --- | --- |
| Backend suite, full | 1:56 (1089 tests) | ~20 s with xdist, ~40 s single process (1113 tests) |
| Backend `-m "not db"` | n/a | 485 tests, ~8 s |
| Backend one group alone | n/a | e.g. engine 381 tests, ~13 s |
| iOS pure logic/decoding | needed app host | `swift test` in `ios/FitnessCore`, 230 tests, ~10 s cold |
| iOS Fast plan | n/a | 260 tests (230 package + 30 app), ~19 s |
| iOS Full plan | 361 tests, ~57 s | 373 tests, 5-16 s incremental |
| pyright (basic) | not run | 0 errors on `core/`, `engine/core/`, `advisor/rules/`, new modules |

Not done / open: `analytics/*` still calls `get_settings()` ad hoc (cached, cheap); `engine/core/lifting.py`
(982 lines) not split; iOS CI workflow never run on a GitHub runner; `deploy/push.sh` gates not
exercised against the real server; `pre-commit install` is up to the developer. Follow-up ideas
remain under "Further suggestions".

## What the survey found

Backend (`backend/`):
- 1089 tests, all green, 1:56 wall. No single slow test: ~370 tests each build a fresh SQLite DB
  through a 14-revision Alembic `upgrade head` (`tests/conftest.py:33`). Measured: one upgrade
  0.2 s, copying a migrated template file 0.2 ms.
- 55 flat `test_*.py` files, no markers, one `conftest.py`, `client` fixture re-defined in 7 files,
  three autouse fixtures that run for every test (`_live_program_in_tmp`, `_auth_throttle_off`,
  `advisor_helpers._clean_settings`). Tests pin engine YAML v2, v3 and v6 in different files.
- Layering is mostly clean (`core` never imports `apps`, no circular imports) with three smells:
  11 loose service modules at `apps/fitness/` top level (`gym_service.py`, `garmin_sync.py`,
  `garmin_workouts.py`, ...); route modules doing persistence (`commit()` in `api/exercises.py`,
  `api/gyms.py`, `api/bodyweight.py`, `api/engine.py`); `db/seed.py:15` importing `engine.config`
  while `engine` imports `db`.
- God modules: `engine/planner.py` 1880, `advisor/service.py` 1307, `advisor/validator.py` 1301,
  `engine/lifting.py` 977, `garmin_workouts.py` 884, `engine/data.py` 723.
- `get_settings()` called 91 times ad hoc; `load_engine_config` (`engine/config.py:560`) re-parses
  YAML on every call including a per-request path in `stats.py:282`; `sleep` injection repeated in
  4 places.
- Tooling: ruff + GitHub Actions (lint, format, full pytest on `backend/**`). No xdist, no
  coverage, no type checker, no pre-commit, no Makefile. `deploy/push.sh` ships the working tree
  without running tests.

iOS (`ios/`):
- One app module + one test bundle hosted in the app (`TEST_HOST`), so every test run launches the
  app. ~400 Swift Testing tests, no tags, no test plan, no iOS CI.
- Good core: pure logic enums (`ProgressModel`, `GymLogic`, `CoachLogic`, ...), `StatsResource`
  caching, pure `Outbox`/`SyncMerge`. Smells: `AppEnvironment.swift` (261 lines) mixes wiring,
  reset/wipe, workout flow and test-mode sniffing; three repositories re-implement the same
  namespace/demo/transport/cache plumbing (`CoachRepository.swift:81-134`,
  `GymRepository.swift:66-113`); `APIClient` has no protocol, so `SyncEngine` is only testable via a
  `URLProtocol` stub.
- Performance: large stats payloads decoded on the main actor (`StatsRepository.swift:~84,~93`);
  transforms recomputed in `body` (`LiftingProgressView.swift:28-31`, `RunningProgressView.swift:36`,
  `TodayView.swift:45-60`); `CachedPlannedSession.item` JSON-decodes per access (`Models.swift:344`);
  full sync on every foreground with no throttle (`FitnessBuddyApp.swift:15-17`).
- Fixtures: `FitnessBuddyTests/Fixtures` (17.5k lines) is a drifted hand copy of
  `docs/api/examples` (generated by `scripts/gen_*_examples.py`); 24 of 26 names match, none is
  JSON-equal. `UILab/build/` is committed.

## Phase 0: safety net (half a day)

Do this first; everything after is a move-and-split refactor and needs a trip-wire.
1. Golden tests for the two outputs most at risk: planner week output for 3 fixed worlds, and
   `advisor/summary.py` JSON for one world. Store as JSON under `tests/golden/`, compare exactly.
2. Add `pytest-xdist`, `pytest-cov` to the dev group; add `--durations=15` locally. Record the
   baseline (time, coverage) in this file.
3. Add a `Makefile` (or `justfile`) at repo root so the commands below have names:
   `test`, `test-fast`, `test-changed`, `lint`, `typecheck`, `ios-gen`, `ios-test-fast`, `deploy`.

## Phase 1: backend test suite (1 day) — biggest win per hour

1. **Template DB.** Session-scoped fixture migrates once into `tmp_path_factory`, each test copies
   the 348 KB file. Expected: ~370 × 0.2 s = ~70 s saved of 116 s. With `-n auto` on top the full
   suite should land around 15-20 s. Delete the hand-rolled Alembic setup in `test_easy_pace.py:243`.
2. **Group by subsystem.** Move files into `tests/{engine,advisor,garmin,importers,api,gyms,sync,
   analytics}/`, each with its own `conftest.py` holding that group's fixtures (`client`, `world`,
   `settings`, fakes). Root `conftest.py` keeps only `session_factory`, `db`, template DB and the
   autouse fixtures. A `pytest_collection_modifyitems` hook adds a marker named after the folder so
   both `pytest tests/engine` and `pytest -m engine` work; register the markers in `pyproject.toml`
   with `--strict-markers`.
3. **Only run what changed.** `make test-changed`: `git diff --name-only origin/main...` mapped to
   groups (`apps/fitness/engine/** -> engine, analytics`; `advisor/** -> advisor`;
   `sources/garmin/**, garmin_*.py -> garmin`; `api/**, core/** -> everything`). Shared files
   (`db/models.py`, alembic, `settings.py`, `conftest.py`) map to the full suite. CI: a matrix job
   per group with the same mapping, plus the full suite on `main`. Optional: `pytest-testmon` for
   local work.
4. **One engine config in tests.** A single `engine_config` fixture pinned to the current version;
   module-level YAML loads in `advisor_helpers.py:39` and `test_easy_pace.py:16` go away. Add a
   test that asserts the pinned version equals the newest file so a bump is noticed.
5. **Autouse hygiene.** Scope `_auth_throttle_off` to the `api` group, `_clean_settings` to
   `advisor`; the three `cache_clear()` calls per test disappear for the engine tests.
6. **Mark DB-free tests.** After Phase 2.3, pure engine tests drop the `db` fixture; `make test-fast`
   runs `-m "not db"` in a few seconds.

## Phase 2: backend architecture (3-4 days, in this order)

1. **Pack the loose modules.** `apps/fitness/{gyms,exercises,bodyweight}/service.py`; one
   `apps/fitness/garmin/` package absorbing `sources/garmin/`, `garmin_sync.py`, `garmin_workouts.py`
   and the mapping code, with `api/garmin.py` staying a thin router. Pure moves, re-exports for one
   release if the CLI or jobs import old paths.
2. **Thin routers.** All `commit()`/`select()` leave `api/*`; each router calls one service
   function and serializes. `get_db` moves from `api/routes.py:21` to `api/deps.py`. Convert
   `session_scope()` in `cli.py` and `garmin_workouts.py` to the same dependency-style factory so
   there is one way to get a session.
3. **Engine: pure core vs store.** `engine/core/` = `lifting`, `running`, `planner`,
   `schedule_rules`, and the pure helpers now in `data.py` (`planned_id`, `base_name_of`,
   `cancel_window`). `engine/store/` = loaders (`data.py`), `persist.py`, `service.py`,
   `config_service.py`. Rule enforced by a test: nothing in `engine/core` imports `sqlalchemy` or
   `apps.fitness.db`. This is what makes Phase 1.6 possible and is the main enabler for faster
   feature work: new progression rules are pure functions with pure tests.
4. **Split `planner.py`** (1880 lines) along its existing seams: week skeleton / lifting slot
   assignment / running assignment / makeup and moves / output assembly. Golden tests from Phase 0
   guard this.
5. **Break the `db -> engine` cycle.** `db/seed.py` needs only `load_raw` and `content_hash`; move
   those to a leaf module (`engine/core/config_files.py` or `config/loader.py`) that imports nothing
   from `db`.
6. **Settings and config caching.** Services take `settings: Settings` in their constructor or
   function signature instead of calling `get_settings()`; routers obtain it via one dependency.
   `load_engine_config`, `db/catalog.py:56`, `gyms.py:131`, `engine/program.py:61` get an
   `lru_cache` keyed by path + mtime (explicit `reload()` for the CLI).
7. **Advisor split.** `advisor/service.py` -> `consultations.py` (create/run/store),
   `approval.py` (approve/reject/apply), `ask.py`; `validator.py` -> `rules/` with one module per
   rule family and the risk classifier. Same public functions, re-exported from `service.py`.
8. **One `Pacer`/clock protocol** replacing the 4 injected `sleep` callables.
9. **Indexes** on `sessions.gym_id`, `sessions.planned_session_id`, `exercise_name_mappings` FKs in
   a new Alembic revision. Low priority; single-user SQLite rarely notices.

## Phase 3: iOS (3-4 days)

1. **Test grouping now, cheaply.** Swift Testing tags per area (`.engine`, `.sync`, `.coach`,
   `.stats`, `.workout`, `.gyms`, `.decoding`) and two `.xctestplan`s wired in `project.yml`:
   `Fast` (pure logic + decoding, no SwiftData container) and `Full`. `make ios-test-fast` runs
   `-testPlan Fast`.
2. **Local Swift package `FitnessCore`** (no SwiftUI/SwiftData imports): `Core/API` DTOs and
   `Coding`, `Outbox`, `SyncMerge`, the stats/coach/gym logic enums and `DashboardTransforms`. Its
   tests run as a plain package test without `TEST_HOST`, so no app launch and much smaller
   incremental rebuilds. This is also what a widget / Live Activity extension (deferred step 7)
   will need to share models with the app without linking the whole app.
3. **One `RemoteRepository` base** (namespace, demo flag, transport, disk cache, `canWrite`) used by
   Stats, Coach and Gyms; `APIClient` behind an `APITransport` protocol so `SyncEngine` tests use a
   fake instead of `RestStubProtocol`.
4. **Split `AppEnvironment`:** composition root only; `WorkoutFlow` and `BackendResetController`
   as their own `@Observable` objects; test mode injected as an init parameter, not read from the
   environment inside production init.
5. **Performance fixes** (each small): decode stats/coach payloads off the main actor and hand the
   decoded value back; cache `CachedPlannedSession.item`; compute dashboard transforms once into
   `@State` in `.task`/`.onChange` instead of in `body`; throttle foreground sync (skip if last
   success < 60 s and outbox empty).
6. **Shared `LoadableContent` view** for the 14 placeholder/empty/error sites.
7. **Fixtures with one source of truth.** iOS tests read `docs/api/examples` directly (XcodeGen
   resource path), delete `FitnessBuddyTests/Fixtures`; add the two gym "server" fixtures to the
   backend generators. A CI contract check decodes every example with the iOS DTOs. Move
   `Resources/Samples` behind a Debug-only resource phase or generate them too.
8. Remove `UILab/build/` from git and ignore it.

## Phase 4: workflow and tooling (1 day, interleave with the above)

- `pre-commit`: ruff, ruff format, swift-format if wanted.
- Type checking: `pyright` basic on `core/` and `engine/core/` first, widen later.
- iOS CI job: `xcodegen generate` + `Fast` test plan on every PR touching `ios/**`; `Full` on main.
- `deploy/push.sh`: refuse a dirty tree, require the current commit's CI to be green
  (`gh run list --commit`), ship `git archive` of HEAD instead of the working tree.
- README refresh (advisor is no longer "later"); `docs/api/examples` regenerated in CI when
  backend changes so iOS contract drift fails the build.

## Further suggestions

- Property-based tests (`hypothesis`) for planner invariants once `engine/core` is pure: no two
  hard sessions on consecutive days, volume hold respected, every planned set within the rep range.
- Coverage report to target the untested iOS areas: `APIClient.makeRequest`, `SettingsStore`,
  Keychain, `NetworkMonitor`.
- A request-timing middleware and structured logs on the backend to catch regressions after the
  config caching work.
- Plan the sunset of the unprefixed `/api/v1/...` routes once the installed app has moved to
  `/api/v1/fitness/...`; keeping both doubles the surface every router change must consider.
- When notifications/widgets/Live Activity come back on the table, build them on `FitnessCore`
  (Phase 3.2) and a small backend `notify/` package; the package exists but is empty today.
